COMPONENT RELATIONSHIP
- ChatGPT Desktop hosts the Codex task and exposes the Computer Use capability.
- The installed Codex Computer Use.app provides the local macOS integration.
- Codex Computer Use.app runs SkyComputerUseService as a separate process.
- Sky uses the macOS Screen Recording and Accessibility permissions to observe
  application UI and carry out requested interactions.
- The crashing process is SkyComputerUseService. ChatGPT Desktop and the
  applications whose UI is being observed remain alive.

AX OWNERSHIP AND TERMINOLOGY
- Each application exposes accessibility objects describing its current UI;
  macOS Accessibility makes those objects available to authorized clients.
- Ordinary application interaction changes the UI and therefore changes the AX
  hierarchy. The reproducer does not directly edit an AX tree.
- "TransformedUIElement" is Sky's observed log category, not an operation the
  user invokes. In this diagnostic, "convert" means Sky reading AX objects and
  building whatever internal/serializable UI-state representation Computer Use
  consumes. That interpretation is inferred from the process role, log category,
  and crash stack; Sky's exact private data model is not publicly documented.

FAILURE CATEGORY
- Sky is reading a native application's accessibility hierarchy to produce a
  Computer Use state snapshot.
- During the read, ordinary UI activity causes accessibility nodes or windows
  to disappear, be replaced, or reorder.
- Common triggers include SwiftUI subtree replacement, transient AppKit panel
  changes, window visibility changes, foreground-app activation, and interaction
  replay while a state request is in flight.
- The target application's identity and business logic are not material to the
  failure; the crash occurs inside SkyComputerUseService.

GENERIC REPRODUCTION SEQUENCE
1. Launch a native macOS test harness with a dynamically changing UI.
2. Have Codex Computer Use request a full state snapshot of the application.
3. While the snapshot/AX observer is active, use normal application actions to
   hide, show, close, or reorder windows and panels, or replace one or more
   SwiftUI view subtrees. This naturally changes the AX hierarchy; do not modify
   accessibility data directly.
4. Optionally activate a second native app or begin replaying captured input to
   increase AX notification and window-tree churn.
5. Request another full state during the transition and repeat as necessary.
6. Sky emits repeated TransformedUIElement errors, traps in Array.remove(at:),
   closes its native pipe, and is relaunched.

LIKELY FAILURE BOUNDARY
This is consistent with stale collection bookkeeping while Sky processes an AX
hierarchy that changes during the read. AX reads fail during window/app churn,
but the same processing path later removes an element using an index that is no
longer valid.
This is a Sky-side resilience defect: ordinary AX invalidation should not be able
to terminate the service.

REQUESTED DEFENSIVE FIX
- Snapshot children before converting them, or serialize conversion and
  invalidation handling per target/tree generation.
- Revalidate an index and tree revision before collection removal.
- Drop, re-resolve, or retry stale AX nodes after UIElementError instead of
  continuing with partially mutated bookkeeping.
- Bound/cycle-check traversal and prune only the invalid subtree.
- Return screenshot-only or partial accessibility state if transformation fails.
- Add a generic regression test that invalidates, removes, and reorders native
  accessibility nodes and windows while a snapshot is in progress.
